Spring AOP 动态代理原理详解

在 Spring AOP 中，代理对象的创建主要有两种方式：

  1. JDK 动态代理
  2. CGLIB 动态代理

本文将结合源码分析这两种方式的实现原理，并总结对比。

1. JDK 动态代理

1.1 触发点

当被代理的目标类 实现了接口 时，Spring 默认使用 JDK 动态代理。

1.3 原理解析

  • 核心类：java.lang.reflect.Proxy
  • 关键接口：InvocationHandler
  • 代理逻辑：所有方法调用都会转发到 invoke() 方法，再由 method.invoke(target, args) 调用目标对象。
  • 特点：
    • 必须有接口
    • 生成的代理类继承自 Proxy 类

2. CGLIB 动态代理

2.1 触发点

当目标类 没有实现接口 时，Spring 会使用 CGLIB 来生成代理。

2.3 原理解析

  • 核心类：Enhancer
  • 关键接口：MethodInterceptor
  • 代理逻辑：通过字节码操作生成目标类的子类，覆盖其方法，加入增强逻辑。
  • 特点：
    • 不依赖接口
    • 通过继承方式生成子类
    • 无法代理 final 类 / final 方法

4.1 获取目标对象

在调用目标方法前，Spring 需要拿到目标对象：

  • advised：保存代理相关的上下文信息
  • getTargetSource()：目标对象的封装
  • getTarget()：真正返回目标对象实例

这一步确保增强逻辑最终能回调到用户实际的业务代码。

5. JDK vs CGLIB 对比总结

特点JDK 动态代理CGLIB 动态代理
是否需要接口必须有接口无需接口
实现方式基于 Proxy + InvocationHandler基于 Enhancer + MethodInterceptor
本质生成实现接口的代理类生成目标类的子类
性能差异JDK 在 JDK8 之前性能略低CGLIB 更快（但生成类耗时略高）
限制不能代理类（只能代理接口）不能代理 final 类 / final 方法

6. 总结

  • Spring AOP 在底层通过 JDK 动态代理 或 CGLIB 动态代理 生成代理对象。
  • Spring 根据目标对象是否实现接口来决定使用哪种方式：
    • 有接口 → JDK
    • 无接口 → CGLIB
  • 无论哪种方式，Spring 都会将拦截器链织入到方法调用前后，实现横切逻辑（如事务、日志、安全等）。
